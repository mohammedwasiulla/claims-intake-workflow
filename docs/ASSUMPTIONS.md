# Assumptions log

| # | Assumption | Why / effect |
|---|---|---|
| A1 | Notes are English, with Indian-style references: `POL-####` (policy) and `CLMNT-####` (claimant). The note ID (`CI-2026-####`) is never treated as a claimant reference. | Matches the dataset; patterns live in `extractors.py`. |
| A2 | Starter labels in the dataset (category, urgency, queue, confidence, manual review) are **not used as input**. They are only a reference in the evaluation. | The pack says they are not perfectly reliable. |
| A3 | Category comes only from incident wording (keyword scoring). A submitter's category (e.g. "user selected travel") and "system category" text are not trusted. If nothing matches, the category is **Unclear / Unclassified**, not a guess. | e.g. CI-2026-0081 says only "accident" -> not assumed to be motor. |
| A4 | Four **core fields** matter for readiness: policy reference, claimant reference, incident date, location. Amount/estimate is reported as missing but does not block readiness. | Keeps "ready" meaningful. |
| A5 | A date counts as `complete` only with day, month and year and a valid calendar day. "19 Mar" (no year) is `partial`; "last week" is `relative`; "2026-04-31" is `invalid`; "10/05/26" is `ambiguous` (day/month order). **The year is never filled in from the received date.** For an ambiguous date the readings not later than the received date are listed in `candidate_iso_dates` but not auto-selected. | No fabricated dates. |
| A6 | More than one different date, policy, claimant, location or amount in one note is reported as `unclear` with all values shown; none is picked silently. | Needs a human. |
| A7 | Manual review is forced by: invalid/ambiguous/multiple dates; unclear or ambiguous category; submitter category differs from note; note says "re-check manually", "do not send to final review until cleaned" or "duplicate may exist"; the note states a mismatch; a remark contradicts the note (e.g. "date missing" but a date is present); third-party reports; incident sequence unclear; duplicate claimant reference inside the batch; **3 or more of the 4 core fields missing/uncertain** (`MANUAL_IF_CORE_ISSUES_AT_LEAST`). | One or two plain gaps = "Needs more information", not manual review. Setting the threshold to 2 raises manual review from 39 to 65 of 85 (see evaluation). |
| A8 | A document listed as provided in one sentence and reported pending/not attached in another is flagged as a conflict (soft signal; may be an earlier state). "(one attachment unreadable)" is **not** attached to a specific document because the note does not say which. | Avoids blaming the wrong document. |
| A9 | "No third-party info since damage was noticed later" is read as *not applicable per the note*, not as a gap (CI-2026-0084). | Only when a reason ("since/because/as") follows. |
| A10 | Urgency: explicit intake marker > explicit words (urgent, asap, immediately) > "emergency admission/visit" > default **Normal** (basis shown as "default - no urgency cue"). `Unknown` is not used because the tool cannot tell "normal" from "unknown" without a cue and a routine default is what ops queues assume. Medical-emergency wording raises urgency of *handling*, not any judgement on the claim. | Basis is always displayed. |
| A11 | Confidence = how reliable/complete the *structuring* is (not the merit of the claim). Score starts at 100 and drops for missing/uncertain core fields, conflicts, gaps, unclear category, etc. High >= 80, Medium >= 55. Reasons are listed. | Transparent, tunable. |
| A12 | Amounts are rupee amounts (`₹`, `Rs`, `INR`; `k`, `L`/lakh). Words like "small amount" are kept as words, no figure invented. | |
| A13 | `source_channel` and `received_date` from the input file are authoritative. If absent, the channel is inferred from the text and labelled "(inferred...)"; received date stays `MISSING`. | |
| A14 | Claimant demands ("please approve my claim") and blame/misconduct statements are recorded as follow-ups/tags for the reviewer, never repeated in the generated summary and never evaluated. | Decision-language guard. |
| A15 | Only the first sentence that carries incident vocabulary is used as the incident excerpt for free-text notes. | Keeps summaries short. |
| A16 | No personal names or phone numbers are extracted. | Privacy; the dataset is synthetic. |
